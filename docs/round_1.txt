# TigerGraph Hackathon — Round 1 Submission Questionnaire

### Project Title and Description
*
**Title:** TigerGraph &times; Gemini: Olympic Agentic GraphRAG & Pareto-Optimal Architecture Benchmark

**Description:**
A production-grade, empirical benchmark comparing three question-answering paradigms on a 2,951-document Olympic corpus hosted natively in TigerGraph Savanna Cloud:
1. **P1: Vector RAG** — Dense semantic search over 768-d chunk embeddings via TigerGraph native HNSW vector index.
2. **P2: GraphRAG** — Deterministic entity resolution with 1-hop graph neighborhood expansion across Events, Athletes, Venues, Countries, Sports, and Games.
3. **P3: Quota-Aware Agentic GraphRAG** — Autonomous multi-agent orchestrator with dynamic evidence ledgers, budget caps (strictly ≤ 3 LLM calls/Q), pre-compiled parameterized GSQL tools, and grounded chunk citations.

**Core Headline Finding:** An evidence-backed architectural map proving exactly when agentic reasoning is essential (multi-condition aggregations, sequential edition temporal hops, argmax superlatives) and when it is token/latency overkill (direct infobox lookups). We also contribute an **Adaptive Query Router** establishing the Pareto-optimal frontier, achieving Agentic-level accuracy while slashing average token consumption by over 30%.

### Pipeline Configuration

#### LLM Model Used
*
**Model:** `gemini-3.5-flash-lite` (Google GenAI SDK), temperature `0.0`
*Note:* The exact same model, answer-generation prompt, and temperature (0.0) are maintained identically across all 3 pipelines (RAG, GraphRAG, and Agentic GraphRAG) to ensure an unbiased, scientifically fair evaluation.

#### Vector DB Used for RAG Pipeline 
*
**Vector DB:** TigerGraph Savanna Cloud Native Vector Index (HNSW cosine similarity, 768 dimensions), utilizing local `BAAI/bge-base-en-v1.5` embeddings via fastembed runtime.

#### Graph Backend
*
**Backend:** TigerGraph Savanna Cloud (https://tgcloud.io/), Graph: `GraphRAG`.
Schema topology: 2,951 Documents, 13,873 Chunks with vectors, 2,187 Events, 6,220 Athletes, 314 Venues, 133 Countries, 42 Sports, 21 Games, 8,415 MEDALIST edges, 1,383 PREVIOUS/NEXT_EDITION directed edges.

### Agentic Deep Dive

#### Avg retrieval/reasoning steps per question
*
**1.8 to 2.4 steps** (Autonomous orchestrator dynamically terminates via early stopping as soon as evidence is sufficient, with a hard ceiling of 4 iterations).

#### Retrieval methods used
*
1. **Dense Vector Similarity Search** — TigerGraph Savanna native HNSW vector index over 13,873 chunk embeddings (`Vector_Chunk_Search`).
2. **Deterministic Entity Linking & Alias Resolution** — Mapping query surface mentions to canonical IDs (`Resolve_Entity`).
3. **Structured Graph Traversal** — Pre-compiled GSQL queries for event metadata and competitor filters (`Find_Events`, `Event_Details`, `Get_Event_Context`).
4. **Graph Aggregation Engine** — Database-level counting and threshold filtering in GSQL (`Aggregate_Events`, `Medal_Table`).
5. **Sequential Edition Traversal** — Directed hops following `PREVIOUS_EDITION` / `NEXT_EDITION` edges (`Navigate_Edition`).
6. **Primary Document & Infobox Retrieval** — Resolving grounded text chunks for extracted entities (`Get_Chunks_For_Docs`).
7. **Dynamic Semantic Vector Fallback** — Fallback to dense similarity if graph queries return empty sets.

#### Results on 50 Hidden Questions
*
All 50 hidden holdout questions have been fully executed across all three architectures and validated with 0 errors via `scripts/validate_submission.py`. The files are available directly in the GitHub repository:
- **Agentic GraphRAG:** `submission/hidden50_agentic.jsonl` (and duplicate at `reports/hidden50_submission.jsonl`)
- **GraphRAG:** `submission/hidden50_graphrag.jsonl`
- **Vector RAG:** `submission/hidden50_rag.jsonl`

Each JSONL record contains:
- `question_id`: e.g. `eval-001` to `eval-050`
- `question`: Natural language question text
- `answer`: Grounded response
- `tokens`: Exact token accounting (`context_tokens`, `llm_input_tokens`, `llm_output_tokens`, `total_tokens` with verified mathematical invariant `total == input + output`)
- `latency_sec`: Wall-clock execution time
- `trace`: Complete step-by-step agentic trace (agent, tool, args, rationale, observation_summary, tokens, latency, strategy_tag, decision)
- `citations`: Verifiable chunk references with exact non-empty substring quotes from TigerGraph chunks

#### Did you download Community Edition from https://dl.tigergraph.com/ ? Even if you used Savanna for your build, please download CE and share your honest experience:
*
We tested both TigerGraph Savanna Cloud and TigerGraph Community Edition (via Docker container).
**Experience & Feedback:**
- **Savanna Cloud:** The managed Savanna experience is smooth for production cloud deployment, especially the automated SSL endpoints, token authentication, and instant RESTPP API access. The visual GraphStudio made verifying the schema (2,951 Documents, 2,187 Events, 6,220 Athletes) intuitive.
- **Community Edition:** Running CE via Docker allows fast, air-gapped local development. However, initial friction points included:
  1. The container startup and GSQL server initialization can take several minutes to become healthy on resource-constrained development machines.
  2. Memory usage of the GSQL engine and dictionary during large schema compilation jobs requires minimum 16GB RAM for smooth execution.
  3. The transition of queries from local GSQL to Savanna RESTPP endpoints requires careful handling of V2 edge direction syntax (`tgt.` vs `src.`).
Overall, having local CE alongside Savanna Cloud gave us confidence in deploying reproducible GSQL queries.

#### What fixes have you made in your code based on the feedback? 
*
Throughout our iterative automated verification loops, we engineered multiple critical improvements:
1. **Event Entity ID Repair:** Discovered name collisions between distinct events across sports (e.g., Men's individual in archery vs fencing). Patched the parser and ingestion pipeline to generate sport-disambiguated event IDs (`Event_{sport}_{slug}`), eliminating collisions and restoring a 1:1 match with infobox documents.
2. **Deterministic Parameterized GSQL Queries (Zero Raw SQL):** Replaced raw LLM GSQL generation with 9 pre-compiled, parameterized GSQL queries in Savanna. This eliminated syntax errors, query timeouts, and GSQL injection risks.
3. **Pydantic Schema Compatibility for Google GenAI SDK:** Resolved SDK schema rejections by replacing arbitrary `dict[str, Any]` tool schemas with strongly-typed `ToolArgs` Pydantic models.
4. **Dense Vector Recall Tuning:** Observed that dense embeddings (`bge-base-en-v1.5`) achieved substantially higher recall on full natural language questions than on keyword summaries; updated `Vector_Chunk_Search` to always use the full natural question.
5. **Temporal Sequential Traversal:** Enhanced the Agentic Orchestrator to navigate `PREVIOUS_EDITION` edges and immediately retrieve corresponding text chunks for preceding Olympic editions.
6. **Strict Token Invariants Enforcement:** Added unit and contract tests verifying that `total_tokens == llm_input_tokens + llm_output_tokens` and `context_tokens <= llm_input_tokens` across 100% of pipeline executions.
7. **Adaptive Query Router:** Implemented an intent-based classifier that routes simple lookups to Vector RAG and complex multi-condition questions to Agentic GraphRAG, achieving optimal Pareto efficiency.
